KEY ARCHITECTURAL FEATURES:
═════════════════════════════════════════════════════════════════════════

1. HETEROGENEOUS DEVICES
   ├─ Sensors (temperature, humidity, motion, occupancy, smoke)
   ├─ Actuators (lights, HVAC, alarms)
   └─ Network devices (gateway, switch, server)

2. CLEAR SEPARATION OF CONCERNS
   ├─ Wireless Edge (IEEE 802.15.4, resource-constrained)
   ├─ Gateway (Protocol translation, 802.15.4 ↔ Ethernet)
   └─ Wired Core (IP-based, standard networking)

3. TWO TRAFFIC CLASSES
   ├─ Monitoring: Periodic, best-effort
   └─ Critical: Event-driven, low-latency requirement

4. SCALABILITY
   ├─ Fixed 12-node baseline (SmartHomeNetwork)
   └─ Parametric N-node variant (ScalabilityNetwork)

5. CROSS-LAYER MODELING
   ├─ Application → Transport → Network → MAC → PHY
   ├─ IEEE 802.15.4 frame limits (127 octets)
   ├─ IPv6/6LoWPAN compression effects
   └─ Fragmentation thresholds (~60-80 B payload)


ADDRESSES & ROUTING:
═════════════════════════════════════════════════════════════════════════

All nodes configured with IPv4 addresses (simulated):
• Wireless nodes (sensors/actuators): Unique IPs via configurator
• Gateway: Bridge IP (both wireless and wired sides)
• Monitoring App: Server IP on wired core
• Core Switch: Transparent L2 device (no IP required)

Routing:
• Global ARP (simplified, for simulation)
• Static routes computed at startup by Ipv4NetworkConfigurator
• Default route through gateway for wireless nodes
• Monitoring app reachable by all sensors
